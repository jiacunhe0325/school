# AI+教育网站改版设计说明

日期：2026-06-01

## 1. 目标

基于 `AI+教育项目建设方案20260513.docx` 与 `AI+教育模块划分.xlsx`，将当前网站从“角色体验型原型”升级为“项目建设方案展示 + 角色化产品体验”的混合型站点。

本次改版目标：

- 首页能够完整讲清项目定位、建设内容、合作生态、价值意义与实施保障。
- 学生端、家长端、教师端、学校端同步调整文案与结构，内容与建设方案保持一致。
- 四端均衡呈现，但信息组织以角色任务为中心，而不是机械平铺 11 个模块。
- 保留当前手工路由方式与现有 React/Tailwind 实现风格，不引入 React Router。

## 2. 已确认范围

- 改版类型：方案展示 + 产品演示结合
- 改版范围：首页、学生端、家长端、教师端、学校端全部同步调整
- 模块映射方式：按角色聚合
- 角色优先级：四端均衡

## 3. 核心信息架构

### 3.1 首页定位

首页作为整站叙事中枢，承担两层任务：

- 第一层：说明“这是什么项目，为什么要建设，建设哪些能力”
- 第二层：把用户分发到不同角色入口，进入可体验的角色工作台

### 3.2 首页内容结构

首页拟采用以下结构：

1. Hero 区
   - 标题突出“AI赋能教育综合平台”
   - 强调“校-师-生-家-机协同育人”
   - 提炼“备课、教学、学习、教研、评价、管理”六大环节闭环
   - 提供四端入口与平台体验入口

2. 项目定位与政策价值
   - 对应文档中的项目核心定位
   - 强调教育数字化、区域教育均衡、个性化教学、创新人才培养

3. 建设内容总览
   - 展示 11 个模块
   - 按以下四组分层展示，而非简单平铺：
     - 教育教学：备课、课堂、思政、教研
     - 个性成长：个性化、科技素养、美育、体质健康
     - 未来空间：未来学习中心
     - 学校治理：学校管理、技术支持与研发中心

4. 场景闭环
   - 用流程式表达讲清从教学准备到学习反馈再到管理决策的闭环
   - 建议顺序：备课 -> 课堂 -> 学习成长 -> 家校协同 -> 教研优化 -> 学校治理

5. 四类角色入口
   - 学生端：学什么、怎么学、如何成长
   - 家长端：怎么看、怎么陪、怎么协同
   - 教师端：怎么备、怎么教、怎么研
   - 学校端：怎么看全局、怎么抓质量、怎么保运行

6. 合作生态
   - 专业指导单位
   - 学术与技术支撑单位
   - 技术支撑单位

7. 价值与实施保障
   - 对应文档中的价值意义与组织/技术/资金/运营/资源保障

8. 收尾行动区
   - 引导继续体验四端

## 4. 四端页面设计

### 4.1 学生端

学生端定位为“个性化成长工作台”，核心强调“今天学什么、为什么学、下一步怎么走”。

主要内容区：

- 今日学习任务：聚合 AI 伴学、分层练习、推荐路径
- 学情与成长画像：展示优势、薄弱点、阶段趋势
- 拓展发展：科技素养、美育、体质健康、未来学习中心体验
- 主题探索：强基计划、竞赛课程、校本选修等自主成长内容

对应模块吸收：

- 个性化模块
- 科技素养模块
- 美育模块
- 体质健康模块
- 未来学习中心
- 思政模块中的成长引导内容

### 4.2 家长端

家长端定位为“家庭协同工作台”，核心强调“看得懂、跟得上、能参与”。

主要内容区：

- 今日孩子状态：学习进度、课堂反馈、情绪与习惯提醒
- 成长报告：学习、德育、健康的多维简报
- 陪伴建议：今晚重点、周末建议、家庭支持方式
- 家校协同：待沟通事项、老师建议、活动通知

对应模块吸收：

- 个性化学习反馈
- 课堂与作业反馈
- 思政与成长评价
- 体质健康模块
- 学校通知与协同事项

### 4.3 教师端

教师端定位为“教学提效工作台”，核心强调“从备课到课堂到教研的一体化支持”。

主要内容区：

- 智能备课：基于学情生成教学重点、资源、练习、课堂活动
- 智能课堂：课堂互动、随堂练习、学情追踪、伴学联动
- 作业与评价：布置、分析、讲评、个体关注
- 教研协同：跨校教研、课例打磨、同课异构、专题研讨
- 专题育人：思政融合、科技素养、美育活动设计

对应模块吸收：

- 备课模块
- 课堂模块
- 思政模块
- 教研模块
- 个性化模块
- 科技素养模块
- 美育模块

### 4.4 学校端

学校端定位为“建设成效与治理驾驶舱”，核心强调“全局可见、过程可管、建设可评估”。

主要内容区：

- 平台运行概览：覆盖学校、班级、教师、学生规模
- 教学质量分析：学科趋势、年级画像、薄弱点分布、教研成效
- 特色建设专题：科技素养、美育、未来学习中心等特色项目进展
- 校园治理：安全、住宿、考勤、用电、物资等管理能力
- 技术与保障：设备运维、数据安全、技术迭代、服务支撑
- 合作与示范：生态合作、成果输出、区域辐射价值

对应模块吸收：

- 学校管理模块
- 技术支持与研发中心
- 其余教学模块的汇总指标与建设成果

## 5. 视觉与内容原则

- 首页气质偏“正式、可信、面向汇报”
- 四端气质偏“具体、可操作、像真实工作台”
- 不直接把 11 个模块重复塞到每个角色端
- 文案避免原型感过强的“假数据堆砌”，更多使用“场景结论 + 能力说明”
- 统一强调“AI赋能”“协同育人”“闭环管理”“个性发展”

## 6. 技术实现原则

- 保持现有手工路由方式
- 尽量复用现有页面壳层与导航结构
- 优先通过重构首页与四端首页内容完成主体改版
- 如原有子页面内容与新方案冲突较大，允许合并、弱化或替换部分旧页面入口
- 修复当前首页中存在的乱码与破损 JSX 文本问题

## 7. 拟实施的页面调整方向

1. 重做首页 `src/HomePage.jsx`
2. 重构学生端首页与关键导航结构
3. 重构家长端首页与二级页面定位
4. 重构教师端首页与主 tab 叙事
5. 重构学校端内容结构
6. 统一整理全站中文文案与视觉语气

## 8. 风险与边界

- 当前项目已有较多原型页面，若全部逐页深改，工作量会明显增加。
- 本轮以“统一叙事与核心页面可用”为优先，不追求把每个旧页面都扩展成完整业务系统。
- 若部分旧页面与新架构不匹配，可保留壳层但重写内容，避免信息冲突。

## 9. 设计自检结论

- 目标与范围一致
- 首页与四端职责边界清晰
- 与用户确认的“结合型站点、按角色聚合、四端均衡”保持一致
- 方案适合进入代码实施阶段
